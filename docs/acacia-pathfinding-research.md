# Acacia pathfinding research

Keep one destination active while the navigation controller finds, validates, and executes the route. The model chooses the destination and risk allowances, such as whether to dig or scaffold. It makes a new decision at arrival or when the controller reports a blocker that needs a different objective, approach, or budget.

## Baritone on Minecraft Java 1.21.4

- **A single goal survives route changes.** Baritone starts planning the next segment before the current one ends, discards the next segment if the player was displaced off it, and starts a valid planned continuation on the same tick. Its composite goal can accept any one of several destinations. Acacia can use the same idea to reach any suitable foothold within the requested area while keeping exact coordinates available for precise interactions. [Pathing behavior](https://github.com/cabaletta/baritone/blob/3ddc8652adaae1500e920d82e26026707a921566/src/main/java/baritone/behavior/PathingBehavior.java#L150-L232) · [Composite goals](https://github.com/cabaletta/baritone/blob/3ddc8652adaae1500e920d82e26026707a921566/src/api/java/baritone/api/pathing/goals/GoalComposite.java#L27-L57)
- **A gap is a movement problem with placement preconditions.** Baritone prices placing a support block, clearing headroom and moving. It considers placing against an adjacent face or sneaking and placing against the last support. In this version it declines to back-place from soul sand or a half slab. Live execution checks crouching before a place click in normal movement mode. Ordinary cancellation during a running traverse waits for a walkable block under the destination. Placement costs also exclude moves when no throwaway block is available, the location is protected, or fluids disallow placement. [Bridge planning](https://github.com/cabaletta/baritone/blob/3ddc8652adaae1500e920d82e26026707a921566/src/main/java/baritone/pathing/movement/movements/MovementTraverse.java#L126-L172) · [Bridge execution](https://github.com/cabaletta/baritone/blob/3ddc8652adaae1500e920d82e26026707a921566/src/main/java/baritone/pathing/movement/movements/MovementTraverse.java#L280-L358) · [Placement cost](https://github.com/cabaletta/baritone/blob/3ddc8652adaae1500e920d82e26026707a921566/src/main/java/baritone/pathing/movement/CalculationContext.java#L259-L275)
- **Pillaring and replanning have completion rules.** The pillar planner checks headroom, availability of a placeable support, and starting terrain. The actuator aligns the player, waits for crouch and height before attempting placement, and only reports success at the requested feet position with support installed. The path executor checks upcoming and current movement costs against the live world and cancels invalid routes at safe boundaries. These spatial checks leave combat exposure to a separate policy. ## Alto Clef

- **Survival work competes for control of the player.** Each tick the highest-priority active chain runs. The user task has priority 50. A fusing creeper raises defense priority based on its fuse, nearby projectile dodging uses priority 65, and urgent mob escape can take priority 70. Lava or fire escape uses priority 100. The food chain yields during lava, urgent movement, or falling. Acacia can use its own health and hazard thresholds while borrowing the priority ordering. - **The task survives an interruption.** A single-task chain retains its task and resets its lifecycle before running again. ## Acacia baseline and live fixtures

The local `minecraft-mine-ai:acacia-foreground` candidate passed 83 tests across navigation orchestration, movement catalogues, and the Mineflayer actuator. The suite already exercises planning ahead while walking, waiting until landing before ordinary cancellation, planning four bridge placements in one run, rejecting lava-admitting moves, sequencing a pillar jump before placement, and declining placement when a mob enters the target cell. This establishes a base for the existing engine. The fixtures use controlled world and bot inputs, so a long bridge or a dynamic threat still needs an isolated Minecraft trial. [Navigation and bridge tests](https://github.com/aibengineering/mine-ai-mcp/blob/de4fef3260424d973bf81d0eaa15ff1a2f73ecff/src/navigation/orchestration/navigation-run.test.ts) · [Movement tests](https://github.com/aibengineering/mine-ai-mcp/blob/de4fef3260424d973bf81d0eaa15ff1a2f73ecff/src/navigation/movements/catalogue.test.ts) · [Actuator tests](https://github.com/aibengineering/mine-ai-mcp/blob/de4fef3260424d973bf81d0eaa15ff1a2f73ecff/src/navigation/mineflayer/bot.test.ts)

1. **One destination, multiple landings.** Use a two-route terrain fixture where the closest approach is blocked. Pass when one model request reaches another supported landing in range. Require final dimension, position, and support evidence.
2. **Bridge budget under replanning.** Cross a multi-block gap with sufficient scaffold and force one replan using a changed support cell. Run the fixture with a budget one block short. Charge confirmed and outstanding placements to the same action across replans. Require settled footing and an actionable stop, including blocks spent and the missing precondition. Include a mixed-stack fixture because the current movement policy selects a scaffold type per search. [Live scaffold selection](https://github.com/aibengineering/mine-ai-mcp/blob/de4fef3260424d973bf81d0eaa15ff1a2f73ecff/src/navigation/mineflayer/movement-policy.ts#L464-L475)
3. **Pillar under changing conditions.** Check one supported climb, one blocked headroom case, and one cancelled climb. Count confirmed placements and require a verified support block before ordinary handoff. Preserve the emergency override for a falling bot.
4. **Local recovery with the same action ID.** Introduce a projectile or attacker partway through a route. Require the guard to wait for a safe handoff, use nearby cover when reachable, and resume toward the destination after the hazard clears. A threat that holds the route should produce one actionable interruption with the limiting hazard. Compare time without physical progress, route completion, damage, and blocks spent across multiple layouts.

## Acacia implementation and checks

- A coordinate objective owns up to six intermediate landings. After a search limit it can try the closest observed node if that node has safe footing and advances toward the original destination. The navigator validates and walks the short route, then restores the destination under the same action ID. Nether navigation and exploration exclude gap jumps with no survivable landing below the arc. The uphill jump fixture verifies that all required headroom is scheduled for clearance.
- `ensure_items` with `loadout=nether` prepares the outbound kit. The portal checks actual equipment and carried supplies. The current targets are full diamond armor, two diamond picks, a diamond sword, an equipped shield and a spare, a bow, 48 arrows, two golden apples, 32 cooked food, gold boots, and 64 scaffold blocks. A receipt identifies any remaining deficit.
- Hunts default to five minutes and a 96-block target radius. These bounds follow the hunt across target changes and survival interruptions. Collection and loadout work can make room at safe action boundaries using a nearby chest or the existing disposal primitive. Settled foreground replies include the inventory delta and free slot count.
- A fresh Java 1.21.4 fixture reached the far side of a lava gap with one `navigate` call, full health, and four blocks spent. Separate fixtures checked the empty-kit portal refusal and built and equipped the kit. One loadout fixture started 22 diamonds short and supplied the other materials. The same request mined the missing diamonds and completed the equipment objective in about 32 seconds.
