# Acacia: explicit goal-focused change list

## Intended behavior

Give the model four flexible goals: get full diamond armor, get blaze rods, get ender pearls, beat the Ender Dragon. They are suggestions in that order, not item-count thresholds, expedition gates, or a fixed checklist. The model can adapt to what the world supplies. The game tools own movement, gathering, and combat execution; keep the model focused on the next milestone and continue pursuing the dragon.

The End fight uses bed cycles automatically when Acacia carries a bed and a safe placement is available. The action stages it at the observed exit fountain, follows the tracked dragon head, checks the blast against local safety, triggers the bed, and requires observed dragon damage. It repeats with remaining carried beds during the perch and otherwise falls back to melee. It does not enforce a bed count, or turn a missing bed into a route blocker.

## Change list

1. **Simplify the route prompt.** Remove preparation inventories, exact rod/pearl/arrow quotas, bow advice, and multi-expedition instructions. Keep only the four milestone suggestions. Hardcore adds one-life awareness and short, local recovery without changing the route.
2. **Remove invalid Nether loadout handling.** The active trace submitted `ensure_items` 57 times and all 57 calls failed. The portal gate requested a Nether preset while the model repeatedly combined `loadout` with item lists or invented placeholder items, triggering schema errors. Remove the preset branch and the portal's request for it; the generic `items` action remains available when the model has a real inventory objective.
3. **Remove strategic inventory gates.** Portal entry checks that the portal is physically usable and confirms the server changed dimension; it does not demand food, arrows, a recommended loadout, or a bed for End respawn. Stronghold location does not stop to recommend supplies.
4. **Make dragon combat own the bed cycle.** Use the recognized fountain geometry, Alto Clef's below-the-pillar stance, block placement receipts, observed dragon-head distance, and a bed-specific power-five blast estimate that ignores the source bed blocks. Confirm damage before repeating; if placement or damage cannot be verified, resume protected melee.
5. **Remove bow-led dragon guidance.** Do not publish the `shoot_dragon` action or ranged crystal choice to the model; keep crystal destruction as a protected melee task. Remove the passive bow tip from status. Nether portal activation still reports a true physical requirement only if a dark portal actually needs activation.
6. **Make chest queries and transfers unambiguous.** Require an explicit `operation`. Allow `inspect` to accept requested item quantities as read-only checks and still report the full chest contents; deposit and withdraw remain explicit transfer operations. The current log shows repeated inspect requests for items that were rejected even though inspection itself is read-only. Later explicit deposits succeeded. A chest covered by sand is a real local obstacle, not a container-transfer bug.
7. **Keep the loop moving.** Use one action for the whole bed attempt or melee perch window; it retains control across waiting and damage confirmation. The model returns to planning only when that action completes, the perch changes, or an actual blocker needs a decision.

## Why this should reduce divergence

The public Mine AI run used the same world seed but a different model, effort level, difficulty, and run harness. It reached its first diamond armor at 22:33, the Nether at 55:10, the first blaze rod at 59:13, the End at 3:31:34, and the dragon kill at 3:56:15 with 388 tool calls. A seed reproduces terrain generation; it does not reproduce portal placement, state, model decisions, or the resulting trajectory. The timings and call total are from the publisher's [winning run transcript and artifacts](https://huggingface.co/datasets/aibengineering/beat-the-game-minecraft/tree/de4bfb91972d263e592276c3a33a8b49d3e75d81).

At the latest captured Acacia activity line (2026-11-15 03:06 UTC), this attempt had 923 tool starts and 232 tool errors. It had made 198 `view_status` calls, 95 `view_blocks` calls, 50 item drops, 57 failed `ensure_items` calls, and 23 `use_container` calls. The container trace mixes malformed inspect requests, valid deposits and one chest covered by sand. An earlier matched-seed pacing sample recorded 260 Acacia calls before diamond armor and 574 before Nether entry, compared with 38 and 88 for Mine AI. This points to repeated inspection and failed policy requests as concrete sources of drag; it does not by itself prove that the prompt or reasoning model caused every extra call. Current and winning runs are not a controlled comparison because model and difficulty differ.

Alto Clef's reusable bed task is a useful execution reference: it recognizes the exit fountain, moves to a fixed nearby stance, places a bed on the pillar, waits for the dragon head to be close, then activates the bed. Its game-level task also opportunistically acquires a bed before the End, but it uses an explicit bed requirement. This change deliberately avoids importing that requirement as another count gate.
