# Mineflayer Web Inventory research

## Recommendation

Borrow the presentation ideas; do not install the plugin as the dashboard inventory renderer. Its most useful ideas are a Minecraft-style slot grid, stack counts, durability bars, and item-name tooltips. This dashboard already receives the slot-level facts needed for those ideas, so they can be rendered in place without adding another server or changing the API.

## Upstream findings

- The current upstream README describes a real-time viewer for multiple Mineflayer windows, with item names and a configurable server. The package is MIT licensed; package metadata declares Node.js 22+ and Mineflayer 4+. [README](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/README.md) · [package.json](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/package.json) · [LICENSE](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/LICENSE)
- The inventory window is drawn over Minecraft's window background, with each item placed at a slot coordinate. The shared canvas renderer draws stack counts and remaining-durability bars. The browser layer detects hovered slots and shows a tooltip; a separate slot list exposes the item name, count, and slot number. [draw.ts](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/shared/draw.ts) · [WindowCanvas.svelte](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/client/src/components/WindowCanvas.svelte) · [SlotList.svelte](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/client/src/components/SlotList.svelte)
- The server sends a full window first and then debounced slot updates. The item view includes a slot index, display name, count, optional texture and durability, and preserves item metadata. Its tracker listens to Mineflayer inventory/window events and rebuilds window state. [messages.ts](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/shared/messages.ts) · [tracker.ts](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/src/tracker.ts) · [index.ts](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/src/index.ts)
- The package starts an unauthenticated HTTP viewer on port 3000 by default, bound to localhost; it can accept caller-provided Express, HTTP, and Socket.IO instances. This is an additional service and protocol surface if used as a dependency. [README: options and remote access](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/README.md#options) · [server.ts](https://github.com/ImHarvol/mineflayer-web-inventory/blob/master/src/server.ts)

## Fit with this dashboard

- `run.mjs` forwards the status response's inventory array to the dashboard. The renderer currently reads only `name` and `count`, even though the pinned Mine AI fork returns `slot`, `location`, `held`, and optional `durability` for each stack. Its `snapshotInventory` covers player inventory slots and equipment and normalizes player-slot positions while a container is open. [run.mjs](../src/run.mjs) · [dashboard.mjs](../web/dashboard.mjs) · [pinned snapshot schema](https://github.com/jakemaly/mine-ai-mcp/blob/12d55d41f2084dca20eb33451d22f839bf8b7101/src/bot-data/bot-status.ts) · [health response](https://github.com/jakemaly/mine-ai-mcp/blob/12d55d41f2084dca20eb33451d22f839bf8b7101/src/server/runtime-host.ts)
- A local renderer can therefore show the 27 main slots, 9 hotbar slots, four armor slots, and off-hand using actual positions. Add a count badge, selected-hotbar highlight, durability bar, and hover/focus label. This leaves Mine AI's status contract unchanged and avoids the plugin's separate HTTP server, Socket.IO channel, and direct `Bot` dependency. Retain a compact-list fallback for older snapshots that lack slot numbers.

## Scope and caveats

The current project runs Node.js 24.15+, so the plugin's declared Node floor is not a blocker. The package itself expects a live Mineflayer `Bot`, while the dashboard consumes the bot's health response; installing it would add an unnecessary viewer server and Socket.IO path when the existing response already has the needed slot data. The MIT license permits code reuse subject to its notice, but the upstream's window/item assets have separate upstream origins; check their asset terms before copying assets directly.
